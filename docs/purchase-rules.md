# Purchase rules

## Verification

- ページを実際に開いて確認した時刻を `last_verified_at` に記録する。
- 検索スニペット、転載、まとめ記事だけでは `high` にしない。
- 「なくなり次第終了」は `ends_at: null` とし、固定締切を推測しない。
- 価格の税・送料・手数料が不明なら確認できた金額だけ保存する。
- ページ消失だけで `ended` と断定せず、公式な終了表示、締切経過、販売主体の告知を確認する。

## Confidence

- `high`: メーカーまたは販売主体の一次情報で、商品、期間、条件、URLを直接確認できる。
- `medium`: 正規小売店や公式SNSで主要項目を確認できるが、一部未確認である。
- `low`: 二次情報のみ、競合、ページ未確認、重要項目欠落。行動確定の根拠にはしない。

## Freshness

| Situation | Target |
| --- | --- |
| 受付中かつ締切24時間以内 | 12時間以内 |
| 受付中かつ締切72時間以内 | 24時間以内 |
| 受付中かつ締切72時間超 | 48時間以内 |
| 受付前 | 72時間以内 |
| 在庫復活・突発販売 | 報告時点 |

目標を超えた情報は `要再確認` とする。

## Priority

- `P0`: 希望商品の締切24時間以内、現在確認できる先着販売、当選後の購入期限24時間以内。
- `P1`: 希望商品の締切72時間以内、本日開始の応募・予約、未対応の重要機会。
- `P2`: 締切72時間より先、受付開始前の準備、発売日販売の条件確認。
- `P3`: 締切なしの監視、低信頼、鮮度超過、条件未確認。

同じ優先度では、希望度、締切、信頼度の順で並べる。応募済み・購入済みは追加行動がない限り今日の行動から外す。

## Human-only actions

Codex は抽選応募フォームの送信、予約・購入の確定、カート投入・決済、会員登録・ログイン、CAPTCHA・待機列・アクセス制限の回避を行わない。必要なページ、期限、条件、手順を提示し、最終操作はユーザーに委ねる。
