# TCG Purchase OS

> 日本で最もトレカ購入機会を取りこぼさない人になる。

TCG Purchase OS は、日本国内のトレーディングカードゲームについて、新商品、予約、抽選、受注販売、再販、発売日販売などの購入機会を発見・整理し、「今、何をすべきか」を判断できる状態をつくるプロジェクトです。

最初から大規模なWebサービスをつくるのではなく、まず Codex を自分専用のTCG購入エージェントとして使い、実際の購入行動の中で調査方法とデータを育てます。再現性が確認できたワークフローを自動化し、最終的には OpenAI API を組み込んだサービスへ発展させます。

## Mission

欲しいTCG商品を正規ルートで購入できる機会を、可能な限り取りこぼさない。

そのために、AIが次の仕事を担います。

- 新商品・予約・抽選・受注販売・再販・発売日販売の発見
- 公式ページや店舗告知からの商品名、価格、期間、条件、URLの抽出
- 同一機会の名寄せと重複排除
- 前回調査からの新規情報・変更・終了の検出
- 情報源と確認日時に基づく信頼性の評価
- 締切、希望商品、対応状況に基づく優先順位付け
- 「今日やること」が分かるレポートの作成

人が担うのは、曖昧な情報の最終確認、規約の確認、抽選応募、予約、決済、購入、そしてカードを楽しむことです。

## Background

TCGの購入情報は、メーカー公式サイト、店舗サイト、公式SNS、アプリ、メール、通販サイトなどに分散しています。開始から締切までが短い抽選や突発的な再販もあり、複数タイトルを人だけで継続的に追うと見落としが発生します。

一方、調査、ページの読解、構造化、比較、変更検出、優先順位付けはAIと相性のよい仕事です。本プロジェクトでは、AIを開発補助だけに使うのではなく、日々の調査と意思決定を行う運用主体として活用します。

自分向けの運用で得られる調査履歴、失敗、訂正、応募・購入結果は、そのまま将来のプロダクト要件と評価データになります。先に実運用で価値と精度を確かめ、その後にサービス化することが本プロジェクトの基本方針です。

## Initial scope

初期の監視対象は、次の3タイトルです。

- Pokémon Card Game
- ONE PIECE CARD GAME
- DRAGON BALL SUPER CARD GAME Fusion World

対象とする購入機会は、新商品、予約、抽選、受注販売、再販、発売日販売です。タイトルや情報源は、精度と運用負荷を確認しながら段階的に追加します。

## AI-first policy

### Phase 1: Codexを自分専用エージェントにする

初期段階では、Codex が情報源の調査、内容の抽出、既存データとの比較、更新、日次レポート作成を行います。人が検索結果を手作業で転記する運用は前提にしません。

繰り返し使って精度が確認できた手順は、プロジェクトの指示、スクリプト、Skill、スケジュール実行へ順次移します。ただし、自動化した結果は、十分な評価が終わるまで人が確認します。

### Phase 2: OpenAI APIをプロダクトの中核にする

サービス化では [OpenAI Responses API](https://developers.openai.com/api/docs/guides/migrate-to-responses#responses-benefits) を中心に、Web search、File search、Function calling、Structured Outputsを組み合わせる方針です。

- Web search: 新しい購入機会の探索
- File search: 店舗ルール、過去の確認内容、運用知識の参照
- Function calling: 商品DBや応募・購入履歴との連携
- [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs): 調査結果を定義済みスキーマへ変換

モデルが文章を要約するだけではなく、根拠付きのデータを保存し、既存データと比較し、必要なアクションを提示できるシステムを目指します。

## Data principles

購入機会の情報では、誤った締切や販売条件が大きな損失につながります。そのため、生成された説明よりも検証可能な根拠を優先します。

各レコードには、少なくとも次の情報を持たせます。

- `source_url`: 根拠となるページ
- `source_type`: 公式、店舗公式、二次情報などの区分
- `last_verified_at`: 最後に内容を確認した日時
- `confidence`: 情報の確からしさ
- `status`: 受付前、受付中、終了、未確認などの状態

確認できない値は推測で補完せず、`null` または未確認として扱います。公式・店舗公式などの一次情報を優先し、二次情報だけで重要な判断を確定しません。訂正履歴も残し、同じ誤りを繰り返さないための評価データとして利用します。

## What this repository is for

このリポジトリは、単なるWebアプリのソースコード置き場ではありません。自分専用エージェントから将来のサービスまでを一貫して育てるための、次の情報の正本です。

- プロジェクトのMission、判断基準、AIと人の役割
- 監視対象と情報源の一覧
- 商品・購入機会・応募・購入履歴のデータ契約
- Codexが調査・更新・報告するときの手順
- 調査、正規化、重複排除、優先順位付け、通知の実装
- 誤り、訂正、見落としを測る評価データと品質指標
- 自分向け運用で得られた知見とサービス要件

ここで確立したデータ形式と運用を、将来のAPI、データベース、通知、Webアプリへ引き継ぎます。

## Boundaries and non-goals

このプロジェクトは、正規の購入機会を見つけ、判断と行動を支援するためのものです。次の行為は目的に含めません。

- 購入BOTによる自動購入や抽選応募
- 同一人物による複数アカウント運用
- サイトの利用規約や技術的制限に反するデータ取得
- 購入機会や利益を保証する表示
- 根拠を確認できない情報の事実としての公開

情報源ごとの利用規約、robots、API・フィードの提供条件を確認し、公式API、許可されたデータ、提携、手動確認を優先します。応募・購入・決済の最終操作は人が行います。

## Success criteria

最初の成功は、アプリを公開することではありません。

1. 欲しい商品の購入機会を、以前より早く、広く、正確に把握できる
2. 朝に「今日やること」を確認すれば、必要な応募・予約・購入判断ができる
3. 発見から結果までの履歴が残り、見落としや誤りを改善できる
4. 同じ手順をCodexとコードで繰り返し実行できる
5. 自分向けに有効だった仕組みを、他のコレクターにも安全に提供できる

この5点を順に満たすことで、「日本で最もトレカ購入機会を取りこぼさない人になる」という目標を、再現可能なプロダクトへ変えていきます。
